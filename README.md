## ใหม่ในรุ่น 2.5.0 (หน้าแรกสำหรับเกษตรกรและผู้รับซื้อ)

เป้าหมายหลักของระบบคือให้เกษตรกรที่มีวัสดุเหลือใช้กับผู้รับซื้อหากันเจอ เพื่อลดการเผาและให้เกษตรกรมีรายได้ หน้าแรกจึงเปลี่ยนเป็น**ตลาดวัสดุ** ส่วนผลการดำเนินงาน (KPI) ย้ายไปหน้า "ผลการดำเนินงาน · เจ้าหน้าที่"

- **หน้าแรก (ตลาดวัสดุ):** ปุ่ม "ฉันมีวัสดุจะขาย" / "ฉันรับซื้อวัสดุ" · ตัวเลขตลาดตอนนี้ (จุดรับซื้อ แปลงประกาศขาย ไร่ ตัน และพื้นที่จัดการแล้วไม่เผา) · แผนที่จับคู่ + รายการ
  - สัญลักษณ์: **วงกลมเขียว + ภาพวัสดุ** = วัสดุพร้อมขาย · **กรอบสีฟาง + รถบรรทุก + ภาพวัสดุ** = จุดรับซื้อ · ตัวเลขมุมขวา = จำนวน
  - ตัวกรอง: ชนิดวัสดุ (ฟางข้าว ใบและยอดอ้อย ซังและต้นข้าวโพด เหง้ามันสำปะหลัง) · จุดรับซื้อ/วัสดุพร้อมขาย · อำเภอ · **ใกล้ฉัน** (เรียงตามระยะทาง)
  - แต่ละรายการบอกคู่ที่ใกล้ที่สุด เช่น "ผู้รับซื้อฟางข้าวใกล้สุด ~8 กม. · 25–30 บาท/ไร่" หรือ "มีฟางข้าวพร้อมขาย ห่าง ~11 กม." และปุ่มเข้าสู่ระบบเพื่อดูเบอร์และตำแหน่งจริง
  - มือถือ: สลับ แผนที่ / รายการ
  - **ความเป็นส่วนตัว:** หน้าสาธารณะแสดงเป็นพื้นที่โดยประมาณ (~5.6 กม.) ไม่มีชื่อ เบอร์ หรือพิกัดจริง ตำแหน่งจริงและเบอร์เห็นหลังเข้าสู่ระบบ (เหมือนเดิม)
- **หน้าผลการดำเนินงาน (`index.html#performance`):** แดชบอร์ดเดิมทั้งหมด (ผลการจัดการ การเพาะปลูก ตลาด) เปิดดูได้โดยไม่ต้องเข้าสู่ระบบ โหลดข้อมูลเมื่อเปิดหน้านี้เท่านั้น · ปุ่ม **เข้าสู่ระบบเจ้าหน้าที่** ใช้หน้าต่างเข้าสู่ระบบเดิม (โครงสร้างและการเข้าสู่ระบบเจ้าหน้าที่ไม่เปลี่ยน) · ลิงก์เดิม `#overview` `#crops` `#market` ยังเปิดหน้านี้
- Apps Script: ไฟล์ใหม่ `Market.gs` (endpoint `market`), `APP_VERSION` 2.5.0 — ไม่เพิ่มชีต ไม่เปลี่ยนข้อมูลเดิม
- ขั้นถัดไป (ยังไม่ทำ): บันทึกการซื้อขายที่ตกลงกันได้ เพื่อวัดรายได้จริงของเกษตรกร

## ใหม่ในรุ่น 2.4.3 (หน้าเว็บเท่านั้น ไม่ต้อง Deploy Apps Script)

- **แท็บการเพาะปลูก**: นำบรรทัด "จัดการวัสดุเหลือใช้ทางการเกษตรแล้ว … ไร่ · ลดก๊าซเรือนกระจก … · มูลค่า … บาท" ใต้การ์ดพืชออก (ตัวเลขชุดนี้อยู่ในแท็บผลการจัดการแล้ว)
- **พิมพ์รายงาน**: หัวตาราง "ชื่อ (หน่วย)" แสดงเป็น 2 บรรทัด ตัดคำระหว่างคำ ไม่หักกลางคำ · ตารางกว้างไม่เกินขอบกระดาษ · แถวสลับสี เส้นรวมชัด · ทั้งฉบับใช้แนวกระดาษเดียว (อัตโนมัติ = แนวนอนเมื่อมีตารางกว้าง) เพราะ Chrome จัดหน้าทั้งเอกสารด้วยความกว้างเดียว การสลับแนวตั้ง/แนวนอนในฉบับเดียวทำให้ตารางล้นขอบ

## ใหม่ในรุ่น 2.4.2 (การ์ดบนรวมเป็นใบเดียว + เข้าสู่ระบบเร็วขึ้น — เฉพาะหน้าเว็บ ไม่ต้อง Deploy Apps Script)

## ใหม่ในรุ่น 2.4.1 (จัดวางส่วนหัวหน้าแรก — เฉพาะหน้าเว็บ ไม่ต้อง Deploy Apps Script)

- **แถบแนะนำ**: ข้อความ "เชื่อมเกษตรกร ผู้รับซื้อ และเจ้าหน้าที่ เพื่อลดการเผา" อยู่ซ้าย พร้อมบรรทัดอธิบายว่าเบอร์เดียวใช้ได้ 3 ระบบ ส่วนปุ่มทางเข้า 3 ปุ่มอยู่ขวา แต่ละปุ่มบอกว่าใช้ทำอะไร (ผู้ขาย: ลงประกาศฟาง ตอซัง เศษวัสดุ · ผู้รับซื้อ: ค้นหาแปลงที่พร้อมขาย · เจ้าหน้าที่: บันทึกและติดตามผลรายอำเภอ) แทนแถบบรรทัดเดียวที่เว้นช่องว่างกลางจอ
- **หัวข้อมูลจังหวัด**: ชื่อ ช่วงปีงบประมาณ เวลาข้อมูล ตัวเลือกปี/อำเภอ และแท็บ รวมอยู่ในกรอบเดียว (เดิมแยก 3 ชั้นและมีบรรทัด "ข้อมูล ณ" ลอยอยู่เดี่ยว ๆ)
- แถบบนสุดกว้างเท่าเนื้อหา โลโก้ตรงแนวขอบเนื้อหา · มือถือจอเล็ก: ซ่อนคำบรรยายใต้ชื่อเว็บ และเนื้อหาไม่ถูกแถบบนบังเมื่อชื่อเว็บขึ้นสองบรรทัด

## ใหม่ในรุ่น 2.4.0 (ตัวตนกลาง — เบอร์เดียวใช้ได้ 3 ระบบ)

- เกษตรกร ผู้รับซื้อ และเจ้าหน้าที่ เข้าด้วย **เบอร์โทรอย่างเดียว** ผ่านตัวตนกลางของ **Agri-Risk Map** — เบอร์เดียวกันใช้ได้กับ Agri-Risk Map และ KPP Smart Agri-Materials · **Mini Super Admin / Super Admin ใช้ชื่อผู้ใช้ + รหัสผ่านเดิม** ไม่ผ่านตัวตนกลาง
- หน้าต่างเข้าสู่ระบบเดิมคงไว้ ข้างหลังเปลี่ยนเป็น: เบอร์ → ตัวตนกลาง → ตั๋วใช้ครั้งเดียว 2 นาที → Apps Script ของ GGH ยืนยันตั๋วกับ Agri-Risk (`id_redeem`) แล้วออก session ของ GGH ตามเดิม · สิทธิ์ยังกำหนดจากชีต `users` / `admins` ของ GGH
- ผู้ใช้เดิมไม่ต้องลงทะเบียนใหม่: เข้าครั้งแรกระบบสร้างตัวตนกลางจากข้อมูลใน GGH ให้ (`ssoProvisionServer` ส่งเฉพาะเบอร์ที่มีใน GGH) · ผู้ที่มีตัวตนจากระบบอื่นแล้วแต่ยังไม่มีบัญชี GGH เลือกประเภทผู้ใช้และติ๊กยินยอมครั้งเดียว (ชื่อกรอกให้)
- เข้าระบบใดแล้ว เปิด GGH (หน้าแรกหรือหน้าเจ้าหน้าที่) ในเครื่องเดียวกันเข้าให้อัตโนมัติ · ออกจากระบบที่ใดก็ออกทุกระบบในเครื่องนั้น · แสดง "เข้าใช้ครั้งก่อน" พร้อมปุ่ม "ไม่ใช่ฉัน" (ระงับทุกระบบทันที)
- Script Property `SSO_MODE` = `optional` (ค่าเริ่มต้น — ถ้าตัวตนกลางล่มหรือปิด หน้าเว็บกลับไปใช้การเข้าแบบเดิมเอง) / `required` (ปิดทางเข้าเดิมด้วยเบอร์ ยกเว้น Mini/Super) / `off`
- เอกสารยินยอม (PDPA) เพิ่มข้อ ๓ เรื่องการใช้ตัวตนร่วมกัน

## รุ่น 2.3.0 (จัดหน้าแรกใหม่)

- **ส่วนหัว:** ข้อความเดียว "เชื่อมเกษตรกร ผู้รับซื้อ และเจ้าหน้าที่ เพื่อลดการเผา" กับปุ่ม [ผู้ขาย] [ผู้รับซื้อ] [เจ้าหน้าที่] แถวเดียว (แทนการ์ด 3 ใบ)
- **แถบขอบเขตข้อมูล "ข้อมูลจังหวัดกำแพงเพชร":** เลือกปีงบประมาณ (ช่วงวันที่อยู่ใต้ช่อง) และอำเภอ ใช้ร่วมกับทุกแท็บ แทนช่องค้นหาอำเภอ
- **แท็บเหลือ 3:** ผลการจัดการ | การเพาะปลูก | ตลาด — ข้อมูลแท็บ "รายงานอำเภอ" เดิม ย้ายเข้า "ผลการจัดการ" เป็นหัวข้อ "รายงานประจำสัปดาห์จากอำเภอ" ระบุที่มา KPP Smart Agri-Materials ชัดเจน (ลิงก์ `#reports` เดิมยังพามาที่หัวข้อนี้)
- **การ์ดผลการจัดการ:** แถบความคืบหน้าเต็มความกว้าง (พื้นที่จัดการ / เป้าหมาย พร้อมพื้นที่เก็บเกี่ยวเป็นบริบท) + การ์ด 3 ใบ ลดก๊าซเรือนกระจก / ปริมาณที่จัดการ / มูลค่าที่จัดการได้ ทุกการ์ดเรียง หัวข้อ → ตัวเลข → หน่วย → หมายเหตุสั้น
- แก้ร้อยละที่ต่ำกว่า 1% ปัดเป็น 0% (เช่น 35 / 70,500 ไร่ แสดง 0.05%)
- ย้ายบรรทัดวิธีคำนวณ (IPCC/EF, มีเทน/ไนตรัสออกไซด์) ไปหัวข้อท้ายหน้า "วิธีคำนวณและแหล่งข้อมูล" มีลิงก์ "วิธีคำนวณ" จากการ์ดก๊าซเรือนกระจก
- ฝั่ง Apps Script เปลี่ยนเฉพาะเลขรุ่น (`APP_VERSION`)

## ประวัติรุ่น 1.4.1

รุ่นนี้เพิ่มการจับคู่ชนิดพืชกับชนิดวัสดุเหลือใช้ทางการเกษตรอัตโนมัติ และแก้การตรวจ Backend รุ่นใหม่กว่าให้ผ่านอย่างถูกต้อง โดยคงโครงสร้าง Google Sheet และระบบเดิม

### สิ่งที่เปลี่ยน

- Frontend ตรวจว่า Backend ไม่ต่ำกว่า `1.3.1` แทนการบังคับให้เลขเวอร์ชันตรงกันทุกตัว
- `1.3.1`, `1.4.0` และ `1.4.1` จึงไม่ถูกปฏิเสธเพียงเพราะเลขเวอร์ชันไม่ตรงกัน แต่ยังตรวจโครงสร้าง response ที่จำเป็น
- เมื่อเลือก `ข้าวนาปี` หรือ `ข้าวนาปรัง` ระบบกำหนดชนิดวัสดุเหลือใช้ทางการเกษตรเป็น `ฟางข้าว`
- เมื่อเลือก `อ้อยโรงงาน` ระบบกำหนดชนิดวัสดุเหลือใช้ทางการเกษตรเป็น `ใบอ้อย`
- เมื่อเลือก `มันสำปะหลัง` ระบบกำหนดชนิดวัสดุเหลือใช้ทางการเกษตรเป็น `เหง้ามันสำปะหลัง`
- เมื่อเลือก `อื่นๆ` ผู้ใช้ระบุชนิดวัสดุเหลือใช้ทางการเกษตรอื่นได้
- Backend บังคับการจับคู่ซ้ำอีกชั้น ป้องกัน Frontend เก่าหรือคำขอที่แก้ไขค่าบันทึกคู่พืช–วัสดุเหลือใช้ทางการเกษตรไม่สอดคล้องกัน
- `Phone` และ `Owner_Telephone` บันทึกเป็นข้อความเพื่อรักษาเลข `0` ด้านหน้า
- ข้อมูลเก่าที่โทรศัพท์เหลือ 9 หลักจากการถูกแปลงเป็นตัวเลข จะถูกเติม `0` ขณะเข้าสู่ระบบ เปรียบเทียบเจ้าของ และแสดงผล
- `Plant_Date` และ `Havest_Date` แสดงในชีตเป็น `yyyy-mm-dd`
- Backend อ่านข้อมูลวันที่เดิมได้ทั้ง `yyyy-mm-dd` และ `d/m/yyyy` รวมถึงปี พ.ศ.
- `setupSystem()` แปลงเฉพาะเบอร์/วันที่เดิมที่ตรวจสอบรูปแบบได้แน่นอน และปล่อยค่าที่กำกวมไว้ตามเดิม
- นำช่อง “ต้องการรับซื้อภายในกี่วันหลังเก็บเกี่ยว” ออกจากแบบฟอร์มผู้รับซื้อ
- คอลัมน์ `buyers!Q` ยังคงอยู่เพื่อไม่เปลี่ยน schema แต่ระบบไม่ใช้ค่านี้กรองหรือแสดงผล และการบันทึกใหม่ใช้ค่าเป็นกลาง `ALL`
- ป้ายพิกัดเกษตรกรเป็น “พิกัดแปลง”
- ป้ายพิกัดผู้รับซื้อเป็น “พิกัดสถานที่รับซื้อ”
- เมื่อเกษตรกรเปิด “แผนที่ & คู่ค้า” ระบบแสดงทุกแปลงของบัญชีที่มีพิกัด พร้อมผู้รับซื้อ `Active`
- ผู้รับซื้อยังเห็นเฉพาะเกษตรกร `Open` ตามตัวกรองเดิม
- ปุ่มโทรและนำทางยังสร้างเฉพาะรายการคู่ค้าฝั่งตรงข้าม

### ความเป็นส่วนตัวของแผนที่

- เกษตรกรได้รับข้อมูลผู้รับซื้อและแปลงของตนเองเท่านั้น
- เกษตรกรไม่ได้รับข้อมูลแปลงของเกษตรกรรายอื่น
- ผู้รับซื้อได้รับเฉพาะข้อมูลแปลงเกษตรกร ไม่ได้รับข้อมูลผู้รับซื้อรายอื่น
- การรวมแปลงของบัญชีใช้ `Owner_Telephone` และใช้ `Phone` เป็นคีย์สำรองสำหรับข้อมูลเก่า
